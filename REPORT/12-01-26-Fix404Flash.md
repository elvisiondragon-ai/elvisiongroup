# Report: Fix "404 Flash" on New Routes
Date: 12/01/26

## Issue
Users reported seeing a "404 Not Found" page for ~1 second before the actual content loads when visiting new routes (e.g., `/watchlist`, `/3000`).

## Root Cause
This is a common behavior in Single Page Applications (SPAs) using Service Workers (PWA):
1.  The **old** Service Worker (cached in the browser) intercepts the request for the new route.
2.  It serves the **old** Javascript bundle (which doesn't know about the new route).
3.  The React Router determines the route is unknown and renders the `NotFound` component.
4.  Simultaneously, the browser detects a new Service Worker version in the background.
5.  The `ServiceWorkerUpdater` component forces a page reload to apply the update.
6.  The page reloads, the new Javascript loads, the route is found, and the correct page renders.
The user sees the `NotFound` component during steps 3-5.

## Fix Implemented
Modified `src/pages/NotFound.tsx` to include a **2-second delay** before showing the actual error message.
- **Before**: Immediate "404 Oops!" -> *Panic* -> Reload -> Content.
- **After**: "Checking routes..." (Spinner) -> Reload -> Content.
- If the page is truly missing (typo), the 404 message appears after 2 seconds.

## Verification
This change is purely UI/UX and masks the update process, preventing the "scary" experience without breaking the PWA's offline capabilities.
